## 一、项目概要

### 1.1 项目定位

VisionBata（代号 VisionDataPlatform，简称 VDP）是一个基于 PyQt6 的**桌面级实时多路摄像头视觉检测平台**。系统在一台 PC 上同时接入最多 4 路摄像头，通过单一共享推理线程执行 AI 目标检测、多目标跟踪、姿态手势识别、矩形物体检测、头部属性分类等多维度视觉分析，并支持 H.264 录像。

### 1.2 集成能力矩阵

| 维度 | 能力 | 后端技术 | 状态 |

## 四、线程模型与信号槽

### 4.1 线程架构

```
┌────────────────────────────────────────────────────┐
│           QApplication 主线程 (GUI)                  │
│  MainWindow → CameraCell × 4 → paintEvent          │
│                   ▲                                 │
│   detection_ready (QueuedConnection)                │
│                   │                                 │
├───────────────────┼─────────────────────────────────┤
│                   │                                 │
│  ┌────────────────┴──────────────────────────────┐ │
│  │   InferWorker (QThread, 共享1个)               │ │
│  │   服务全部 4 个槽位，双缓冲 _FrameSlot           │ │
│  └───────────────────────────────────────────────┘ │
│                   ▲                                 │
│     submit_frame (DirectConnection)                 │
│                   │                                 │
├───────────────────┼─────────────────────────────────┤
│                   │                                 │
│  ┌────────────────┴──────────────────────────────┐ │
│  │ SingleCameraWorker × N (QThread, 每路1个)      │ │
│  │ PyAV DirectShow 拉流 → frame_ready 信号         │ │
│  └───────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘

录像: ThreadPoolExecutor(max_workers=4) 守护线程池
```

### 4.2 QThread 子类清单

| 类名 | 文件 | 行号 | 职责 |
|------|------|------|------|
| `InferWorker` | `ai/inference.py` | ~296 | 共享推理线程（主应用使用） |
| `SingleCameraWorker` | `camera/capture.py` | ~16 | PyAV 摄像头采集（主应用使用） |
| `CaptureThread` | `demo.py` | ~69 | 替代采集（仅 demo） |
| `InferenceThread` | `demo.py` | ~107 | 替代推理（仅 demo） |

**注意**：demo.py 中存在 `CaptureThread` 和 `InferenceThread` 两个平行的 QThread 子类，与主应用的 `SingleCameraWorker`/`InferWorker` **功能重复但实现不同**，存在两个独立线程模型。

### 4.3 pyqtSignal 定义清单

| 类 | 信号 | 参数 | 用途 |
|------|------|------|------|
| `SingleCameraWorker` | `frame_ready` | `int, object` | 采集帧就绪（camera_id + ndarray） |
| `SingleCameraWorker` | `error_occurred` | `int, str` | 采集错误通知 |
| `InferWorker` | `detection_ready` | `int, list` | 推理结果就绪（slot_id + detections） |

| `SplashScreen` | `finished` | 无 | 启动动画完成 |
| `CameraCell` | `double_clicked` | `int` | 双击放大 |
| `CaptureThread` | `frame_ready` | `object` | demo 采集帧 |
| `InferenceThread` | `result_ready` | `object` | demo 推理结果 |

### 4.4 信号槽连接流程

```
MainWindow._on_camera_selected(slot_id, device_name)
  │
  ├─ SingleCameraWorker 启动
  │    ↓ frame_ready(slot_id, frame)
  │    ├─→ CameraCell.update_frame        [QueuedConnection, 显示]
  │    ├─→ InferWorker.submit_frame       [DirectConnection, AI 开启时]
  │    └─→ _on_frame_for_recording        [录制开启时]
  │
  ├─ InferWorker 运行
  │    ↓ detection_ready(slot_id, detections)
  │    └─→ CameraCell.update_detections   [QueuedConnection, 叠加绘制]
  │
  └─ 关闭顺序（closeEvent）:
       录像.stop_all → 摄像头.stop_all → 推理.wait(3s) → blockSignals(True)
```

### 4.5 单点故障分析

| 组件 | 故障影响 | 影响范围 | 严重程度 |
|------|----------|----------|----------|
| InferWorker 线程崩溃 | 全部槽位无 AI 检测结果 | 4 路全部 | **高** |
| MainWindow | 整个应用崩溃 | 全部 | **高** |
| 单个 SingleCameraWorker | 对应槽位无画面 | 1 路 | 低（其他 3 路不受影响） |

## 五、数据流全景

### 5.1 端到端数据流

```
USB 摄像头（物理设备）
  │
  ▼ PyAV DirectShow (dshow, BGR → RGB ndarray)
SingleCameraWorker (QThread)
  │
  ├──→ CameraCell.update_frame        [QueuedConnection, 30fps 显示]
  │       QImage → paintEvent GPU 合成
  │       ├─ 背景缓存
  │       ├─ 视频帧（支持水平翻转）
  │       └─ 检测叠加层（框/骨架/polygon/标签）
  │
  ├──→ InferWorker.submit_frame       [DirectConnection, AI 开启时]
  │       _buffers[slot].frame = frame  (双缓冲无锁写)
  │         │
  │         ▼ run() 主循环
  │       ┌─ if frame_id % stride == 0: [命中推理帧]
  │       │   1. _denoise_frame()             [none/bilateral/nl_means]
  │       │   2. _run_inference()             [OnnxYolo/Yolo26/Uhd 分支]
  │       │   3. DetectionTracker.update()    [UKF/MCUKF/Manifold + AUTO]
  │       │      ├─ predict + correct         [卡尔曼滤波]
  │       │      ├─ ROI 重检测回调             [丢失目标找回]
  │       │      ├─ HSV 颜色直方图更新         [外观特征]
  │       │      ├─ ReID 嵌入更新              [重识别]
  │       │      └─ _FilterAdaptor 评估        [自适应切换]
  │       │   4. _attach_head_attributes()    [CHC 头部属性]
  │       │   5. _attach_gestures()           [身体姿态手势]
  │       │   6. _run_rectangle_detection()   [Canny + 轮廓]
  │       │   7. final_dedupe()               [最终去重]
  │       │   8. _HealthMonitor.update()      [健康检查]
  │       │
  │       └─ else: [跳帧]
  │            tracker.predict_step()          [卡尔曼填充]
  │            + 复用上次 non-person 结果
  │         │
  │         ▼
  │       detection_ready.emit(slot_id, detections)
  │
  └──→ VideoRecorder.push_frame       [录制开启时]
        消费者队列 → ThreadPoolExecutor
        → RGB→yuv420p → H.264(ultrafast) → MP4
```

### 5.2 坐标约定

- **全程归一化 `[0, 1]`**：检测框、关键点、多边形顶点在内部全部归一化
- **绘制映射**：`paintEvent` 中乘以控件宽高还原像素坐标
- **水平翻转**：`x = 1.0 - x`（当翻转选项开启时）
- **OBB polygon**：`[(x1,y1), (x2,y2), (x3,y3), (x4,y4)]` 四边形顶点
- **跳帧 polygon 外推**：`vx' = (vx - cx) × scale + cx_new`

### 5.3 关键设计决策

| 决策 | 理由 | 稳定性 |
|------|------|--------|
| 1 个共享推理线程 | 避免 GPU/CPU 资源争抢和多模型实例 | ✅ 不宜更改 |
| 纯 NumPy 卡尔曼 | 零外部滤波库依赖，完全可控 | ✅ 不宜更改 |
| 归一化坐标 | 分辨率无关，跨摄像头一致 | ✅ 不宜更改 |
| QSettings 持久化 | 跨会话配置记忆 | ✅ 不宜更改 |
| 信号槽线程解耦 | 独立生命周期，线程安全 | ✅ 不宜更改 |
| Detection dict 兼容层 | 旧模块仍使用 dict 形式 | ⚠️ 可逐步迁移 |

### 7.2 问题模式

1. **`ai/inference.py` 裸 except**：多处使用 `except Exception` 或裸 `except:`，捕获 KeyboardInterrupt/SystemExit 风险

│       └─ 通过 bypass 桥接  │    ├─ Track               │
│                          │    └─ Frame                │

### 12.4 评估

| 维度 | 现有架构 (ai/) | 新架构 (visioncore/) |
|------|---------------|---------------------|
| **文档** | ❌ 几乎无 docstring | ✅ 100% 模块级 docstring |
| **测试** | ❌ ~10% 覆盖 | ✅ 良好覆盖（~64 测试） |
| **类型安全** | ⚠️ dict 混用 | ✅ 严格 dataclass/frozen |
| **模块边界** | ⚠️ 模糊（InferWorker 承担过多） | ✅ 清晰（manager/lifecycle/store 分离） |
| **集成状态** | ✅ 生产使用 | ⚠️ 通过 bypass 桥接，未完全集成 |
| **依赖方向** | ✅ 无环 | ✅ 仅 TYPE_CHECKING 依赖 ai |

### 12.5 迁移状态

- `ai/inference.py` 中已通过 `sys.modules` bypass 模式创建 TargetManager 实例
- `visioncore/core/adapters.py` 使用 `TYPE_CHECKING` 桥接，避免运行时循环依赖
- 迁移为**渐进式**：新功能走 visioncore，旧功能保留在 ai/
- 两个系统当前共存，visioncore 作为 "shadow system" 运行
