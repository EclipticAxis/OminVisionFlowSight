## 一、项目概要

### 1.1 项目定位

VisionBata（代号 VisionDataPlatform，简称 VDP）是一个基于 PyQt6 的**桌面级实时多路摄像头视觉检测平台**。系统在一台 PC 上同时接入最多 4 路摄像头，通过单一共享推理线程执行 AI 目标检测、多目标跟踪、姿态手势识别、矩形物体检测、头部属性分类等多维度视觉分析，并支持 H.264 录像。

**自 v1.0 审计后的关键架构演进**：新增 `visioncore/eventbus/` 发布-订阅基础设施（纯标准库，线程安全），实现 TargetManager 生命周期事件的自动发布。EventBus 通过 Shadow Integration 模式接入 InferWorker，当前不消费事件（验证管道畅通），为后续里程碑的告警/日志/UI高亮等消费端奠定基础。

## 四、visioncore/eventbus/ 新模块深度分析

### 4.1 模块定位

`visioncore/eventbus/` 是 Milestone 3（EventBus 基础设施）的核心交付物。作为一个**纯标准库、线程安全的发布-订阅系统**，它为 VisionCore 目标管理层提供了类型化的事件发布能力，是后续告警/日志/UI高亮等消费端的通信中枢。

### 4.2 文件结构

```
visioncore/eventbus/          (6 文件, 1,286 行)
├── __init__.py       (83 行)  包入口：导出 EventBus/Subscriber/Dispatcher/
│                              EventListener/DebugEventLogger + 6 事件类
├── bus.py            (480 行) ★核心：EventBus 发布-订阅中心
├── events.py         (241 行)  类型化事件层级（BaseEvent + 5 子类）
├── subscriber.py     (175 行)  Subscriber dataclass + EventListener 别名
├── dispatcher.py     (90 行)   同步分发引擎（异常隔离）
└── debug_logger.py   (217 行)  可切换通配符调试观察者
```

### 4.3 架构设计


### 4.4 关键设计决策

| 决策 | 说明 |
|------|------|
| **同步分发** | 回调在发布线程上同步执行，保证事件顺序 |
| **锁外分发** | `publish` 在锁内快照订阅者、锁外执行回调，避免死锁 |
| **RLock 可重入** | 回调内可安全地 publish 嵌套事件 / unsubscribe 自己 |
| **双模式订阅** | 字符串键（`"target.lost"`）用于简单场景；类键（`TargetLostEvent`）通过 `isinstance` 实现类型安全 |
| **通配符 `*`** | 接收所有事件，供 DebugEventLogger 使用 |
| **异常隔离** | 单个回调崩溃不影响其他订阅者或发布者 |
| **软删除** | unsubscribe 仅标记 `Subscriber.active=False`，in-flight 分发安全跳过 |
| **类订阅索引优化** | 类订阅仍按 event_type 字符串索引（`_subscribers["target.lost"]`），matches 做 isinstance 二次过滤 |
| **向后兼容 core.Event** | 字符串订阅同时接受类型化事件和轻量 core.Event |

### 4.5 集成状态：Shadow Integration

```
Tracker 产生 detections
    │
    ▼
detections_to_tracks(detections)     [converters.py]
    │
    ▼
TargetManager.update_targets(tracks) [manager.py]
    ├─ create_target  → _emit_lifecycle_event → TargetCreatedEvent  → EventBus.publish
    ├─ mark_lost      → _emit_lifecycle_event → TargetLostEvent     → EventBus.publish
    ├─ mark_recovered → _emit_lifecycle_event → TargetRecoveredEvent→ EventBus.publish
    ├─ lock_target    → _emit_lifecycle_event → TargetLockedEvent   → EventBus.publish
    └─ mark_removed   → _emit_lifecycle_event → TargetRemovedEvent  → EventBus.publish
                                                         │
                                                    【当前无订阅者】
```

**关键特征**：
- InferWorker 创建 EventBus 并通过构造注入 TargetManager
- TargetManager 自动发布事件（无额外调用）
- 当前无任何消费者订阅事件 → `publish()` 返回 0，O(1) 空操作
- InferWorker/GUI 均不消费事件
- `_bypass_update_targets` 失败不影响推理流程（try/except 静默）

## 六、数据流全景

### 6.1 端到端数据流（含 EventBus 旁路）

```
USB 摄像头（物理设备）
  │
  ▼ PyAV DirectShow
SingleCameraWorker (QThread)
  │
  ├──→ CameraCell.update_frame        [QueuedConnection, 显示]
  ├──→ InferWorker.submit_frame       [DirectConnection, 推理]
  │       │
  │       ▼ run() 主循环
  │       ┌─ 去噪 → 多后端推理 → DetectionTracker.update → 属性附加 → 去重
  │       │
  │       ├─ detection_ready.emit → CameraCell.update_detections
  │       │
  │       └─ _bypass_update_targets(slot_id, detections)  ★ Shadow
  │            │
  │            ▼ detections_to_tracks(detections)
  │            ▼ TargetManager.update_targets(tracks)
  │                 ├─ create → TargetCreatedEvent  → EventBus.publish
  │                 ├─ mark_lost → TargetLostEvent → EventBus.publish
  │                 ├─ mark_recovered → TargetRecoveredEvent → ...
  │                 ├─ lock → TargetLockedEvent → ...
  │                 └─ mark_removed → TargetRemovedEvent → ...
  │                                       │
  │                                  【当前无订阅者】
  │
  └──→ VideoRecorder.push_frame       [录制开启时]
```

### 6.2 双事件系统并存

项目现存在**两套独立的事件/信号体系**，互不干扰：

| 体系 | 技术 | 用途 | 类型 |
|------|------|------|------|
| PyQt 信号槽 | `pyqtSignal` + `connect` | 线程间数据传递（采集→推理→显示→录像） | Qt 原生 |
| VisionCore EventBus | `EventBus` + `publish/subscribe` | 目标生命周期事件（创建/丢失/恢复/锁定/移除） | 纯标准库 |

两套体系独立运行：
- PyQt 信号槽处理实时帧数据流（高频，每帧）
- EventBus 处理目标状态变更事件（低频，仅状态切换时）
- EventBus 的回调在推理线程内同步执行，不阻塞 Qt 事件循环

### 12.2 EventBus 风险评估

**EventBus 本身不引入新的高风险项**。理由：
- 构造注入模式，`event_bus=None` 向后兼容
- `_emit_lifecycle_event` 异常隔离（P1 已修复）
- `_bypass_update_targets` 有 try/except 保护
- 当前无订阅者 → O(1) 空操作零性能影响
- 单线程（推理线程）同步分发，不引入并发复杂度（当前阶段）

唯一潜在风险：未来添加订阅者后，长耗时回调可能阻塞推理线程。当前架构中分发是同步的，建议后续里程碑评估异步分发需求。
